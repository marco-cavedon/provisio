# 0015 — CI/CD with GitHub Actions

- **Status:** Accepted
- **Date:** 2026-10-06

## Decision outcome

### Continuous integration

- GitHub Actions, triggered on **pull requests** and on **pushes to `main`** — not on every push to every branch.
- Work happens on branches merged through pull requests; `main` is protected and requires green checks.
- One job per component with **path filters**, so a change only runs the checks it affects ([ADR 0009](0009-monorepo.md)).
- Pipelines are added **incrementally**: each component ships with its own CI job when it is created.
  No placeholder pipelines for components that do not exist yet.
- Actions are kept up to date by Dependabot; workflows run with least-privilege `permissions`.

### Continuous delivery

- There is no hosted environment to deploy to. Delivery means **publishing Docker images** of the project's
  services to GitHub Container Registry on every version tag.
- The demo Compose file pulls published images, so `docker compose up` does not need to build anything locally
  ([ADR 0007](0007-local-runtime-with-docker-compose.md)).

### Bootstrap scope

At bootstrap the repository contains documentation only, so CI runs: secret scanning (gitleaks),
Markdown lint, and an offline check of internal links.

## Consequences

### Positive

- Fast, relevant feedback on every pull request; a ready-to-run demo from published images.

### Negative

- Branch protection and PRs add a little ceremony to solo development — accepted deliberately.
